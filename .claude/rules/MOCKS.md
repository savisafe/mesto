# Моки (mock-данные)

## Правило

Моки разрешены **ТОЛЬКО** если эндпоинт невозможно реализовать на sl-back или sw-back
(нет нужного сервиса, API третьей стороны недоступен, бэк-команда подтвердила невозможность).

Если бэк может отдать данные — мок **НЕ** создаётся, используется реальный API.

---

## Паттерн (референс: checklist)

### 1. Флаг в файле API модуля

```ts
export const USE_<MODULE>_MOCK = false;
const MODULE_API_URL = USE_<MODULE>_MOCK ? '/api-mock' : API_URL;
```

Флаг по умолчанию **ВСЕГДА `false`**. Включать только локально для разработки.
В `dev` / production мок никогда не должен быть активен.

### 2. Мок-роуты

Размещать в `src/app/api-mock/<сервис>/<эндпоинт>/`:

- `route.ts` — Next.js route handler, возвращает JSON из мок-файла.
- `<name>.mock.json` — примерный JSON-ответ, повторяющий реальную структуру DTO.

Route handler — минимальный:

```ts
import { NextResponse } from 'next/server';
import type { ResponseType } from '@/app/<module>/model/<module>.types';

const mock = require('./<name>.mock.json') as ResponseType;

export async function POST(): Promise<Response> {
  return NextResponse.json(mock);
}
```

### 3. JSON-мок

- Структура должна **точно** повторять реальный DTO (те же поля, те же типы).
- Данные — правдоподобные, не `"test"` / `123`.
- Файл не должен содержать секретов, реальных ID пользователей, токенов.

### 4. Ограничение размера

- JSON-мок **не более 1000 строк** (≈ 3–5 объектов в массиве, достаточно для проверки UI).
- Если реальный ответ API содержит сотни/тысячи записей — в мок кладём **минимальную репрезентативную выборку**: 3–5 записей, покрывающих основные кейсы (разные статусы, пустые поля, граничные значения).
- Запрещено коммитить JSON-файлы > 1000 строк.
- Если мок содержит вложенные массивы — каждый вложенный массив тоже сокращай до 2–3 элементов.

### 5. Большие JSON для локальной отладки

Если для разработки нужен полный дамп API (сотни/тысячи записей):

1. Называй файл с суффиксом `.local`: `<name>.local.mock.json`.
2. Файлы `*.local.mock.json` добавлены в `.gitignore` — они **не попадают** в репозиторий.
3. В `route.ts` по умолчанию используется короткий мок (`<name>.mock.json`).
   Для локальной отладки разработчик вручную переключает путь на `.local.mock.json`.
4. Не храни локальные дампы дольше, чем нужно для задачи.

---

## В описании MR обязательно указать

- Почему мок, а не реальный API (что именно невозможно на бэке).
- План замены мока на реальный эндпоинт (когда бэк будет готов).

## Чек-лист

- [ ] Бэк-команда подтвердила, что эндпоинт нельзя сделать на sl-back / sw-back.
- [ ] Флаг `USE_*_MOCK = false` по умолчанию.
- [ ] Мок-роут в `src/app/api-mock/`, JSON повторяет реальный DTO.
- [ ] JSON-мок ≤ 1000 строк (3–5 записей, репрезентативная выборка).
- [ ] В MR указана причина мока и план замены.
