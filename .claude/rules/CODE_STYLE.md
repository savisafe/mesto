# Единые правила кода

## Общие

- Компоненты: PascalCase. UI-примитивы (`src/ui/*`) — `const Component = (props: Props) => {}`; страницы (`src/views/*`) — `export default`.
- Props: `interface Props` или `interface <Name>Props`, camelCase, boolean-пропсы в формате `is/has/can`.
- Обработчики: `handleX`; в JSX передавай ссылки на обработчики (`onClick={handleX}`), а не лишние inline-вызовы.
- JSX держи простым: сложные вычисления выноси в переменные, хелперы или хуки.
- Избегай дублирования кода: общую логику выноси в переиспользуемые хелперы/хуки/компоненты (пример: проверку доступа держим в `services/_access.ts`, а не копируем в каждый сервис).
- Не объявляй компоненты внутри других компонентов; декомпозируй на уровне файлов (пример: `CalendarDayGrid` вынесен из `CalendarPage`).
- Импорты: алиас `@/*` (→ `src/*`). Прямые импорты — норма проекта; баррель `index.ts` заводи только при реальной необходимости (как `ui/form`).
- Типизация: избегай `any` (сейчас в `src` его нет — держим планку). Доменные типы выводи из Drizzle-схемы (`Client`, `NewClient`, `UserRole` из `@/db/schema`), а не дублируй вручную. Используй `unknown` + type guards при необходимости.
- Не злоупотребляй type assertions через `as`; только когда без этого нельзя.
- Побочные эффекты: контролируй зависимости `useEffect/useMemo/useCallback`, не допускай скрытых гонок и утечек.
- Публичные контракты модулей (`ServiceResult`/`ActionResult`, `*Input`-типы сервисов) не меняй без явной причины и без отражения в местах использования.
- Комментарии в коде — только при необходимости (например, `TODO`); пояснения к решению выноси в описание PR.
- Предпочитай `implicit return`, где это упрощает код и не вредит читаемости.
- Крупные компоненты декомпозируй. Ориентир — ~250–300 строк; сложные экраны (календарь, расписание) разбивай на подкомпоненты.
- Не используй `forwardRef` и другие legacy-подходы React без критической необходимости.
- Не используй `eslint-disable` без критической необходимости и явного согласования.
- Не оставляй пустые callback-функции; если обработчик не нужен — не передавай его.
- Всегда обрабатывай ошибки (API, async-логика, граничные состояния UI).

## Стили

- Tailwind CSS 4 (`@import "tailwindcss"` в `globals.css`).
- Цвета и токены — CSS-переменные в `src/app/globals.css` (`:root` + `@theme inline`); не хардкодь hex прямо в компонентах.
- Условные классы — через `clsx`.

## Структура проекта (слои)

Проект **не на FSD**. Раскладка по техническим слоям; новый код клади в соответствующий слой:

- `src/app/*` — роуты App Router (страницы) и `app/api/*` (route handlers, в т.ч. внешний API `app/api/external/*`).
- `src/views/*` — страничные компоненты (UI экрана), `export default`.
- `src/ui/*` — переиспользуемые UI-примитивы без знания домена (button, modal, form, select…).
- `src/services/*` — серверная бизнес-логика и доступ к БД. Обязательно `import 'server-only'`. Покрывай тестами (`*.test.ts` рядом).
- `src/actions/*` — server actions (`'use server'`): тонкие обёртки над `services`, маппят `ServiceResult` → `ActionResult` и делают `revalidatePath` после мутаций.
- `src/lib/*` — инфраструктура (auth, session, crypto, external-api), с тестами.
- `src/hooks/*`, `src/contexts/*` — клиентские хуки и контексты (`AuthContext`, `BusinessContext`, `NotificationContext`).
- `src/db/schema/*` — Drizzle-схемы и выводимые типы; `src/db/index.ts` — клиент БД.
- `src/routes/routes.ts` — единый источник путей. Новый маршрут добавляй сюда, не хардкодь строкой.

## Серверный код, данные и доступ

- Сервис, который читает/меняет данные: сперва `getCurrentUser()` → `UNAUTHORIZED`, затем `checkBusinessAccess(businessId, userId)` → `FORBIDDEN`.
- Все запросы к БД фильтруй по `businessId` (изоляция бизнесов). Проверки доступа недостаточно — фильтр обязателен.
- Внешний API (`app/api/external/*`): аутентификация через `requireAuth(req, '<scope>')`, ответы через `apiOk`/`apiError`. `businessId` бери из `auth.ctx`, а не из тела запроса.
- Ожидаемые ошибки возвращай через `ServiceResult`/`ActionResult` (`{ ok: false, error, code }`), а не `throw`.
- Валидируй вход: `trim`, проверки на пустоту, clamp пагинации (`MAX_PER_PAGE`).
- `NEXT_PUBLIC_*` — только клиентские несекретные значения. Секреты, ключи, токены, списки доступа — server-only env.
- Менял схему (`db/schema/*`) — сгенерируй миграцию (`npm run db:generate`).
- Моки — по правилам `MOCKS.md` (флаг `USE_*_MOCK = false` по умолчанию).
